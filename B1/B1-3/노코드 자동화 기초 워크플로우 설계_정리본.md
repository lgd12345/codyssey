# 노코드 자동화 기초: 워크플로우 설계

> 반복 업무를 분석하고, 코딩 없이 자동화 워크플로우를 설계·구현하며, 서로 다른 자동화 도구를 비교하는 과제입니다.

---

## 과제 한눈에 보기

이 과제에서는 **2개의 프로젝트**를 수행합니다.

| 구분 | 해야 할 일 |
|---|---|
| 프로젝트 1 | 동일한 자동화 워크플로우를 서로 다른 **2개 이상의 도구**로 구현하고 비교 |
| 프로젝트 2 | 자유 주제로 반복 업무를 정하고, 자동 실행되는 워크플로우를 직접 설계·구현 |

두 프로젝트 모두 설계 문서만 작성하는 것이 아니라, **실제로 동작하는 자동화 워크플로우**를 만들어야 합니다.

### 반드시 포함해야 하는 기본 구조

- Trigger 1개 이상
- Action 2개 이상
- 조건 분기(Filter/Router) 1개 이상
- 조건 분기의 각 경로가 실제로 1회 이상 실행된 결과
- 구현 화면 캡처
- 실행 결과 화면 캡처

---

## 먼저 알아야 할 핵심 개념

### Trigger

자동화가 시작되는 이벤트입니다.

예를 들어 Google Form에 응답이 제출되거나, Google Sheets에 새로운 행이 추가되는 상황이 Trigger가 될 수 있습니다.

### Action

Trigger가 발생한 뒤 자동으로 실행되는 처리 동작입니다.

예를 들어 Google Sheets에 데이터를 기록하거나 Slack에 메시지를 보내는 작업이 Action입니다.

### Filter / Router

입력된 데이터의 조건에 따라 처리 경로를 나누는 기능입니다.

예를 들어 점수가 80점 이상이면 합격자 경로로 보내고, 80점 미만이면 다른 경로로 보내는 구조입니다.

# 1. 미션 소개

매일 아침 이메일을 확인하고 스프레드시트에 옮겨 적고 팀 채널에 요약을 공유하는 루틴을 떠올려 봅시다.

한 번에 5분이면 끝나는 일이지만 하루에 열 번 반복되면 어느새 50분이 사라집니다.

> "이걸 자동으로 돌릴 수 없을까?"

이렇게 생각하고 방법을 찾아보면 코드를 짜야 한다는 벽에 막히고, 결국 다시 수작업으로 돌아간 경험이 있을 겁니다.

노코드 자동화 도구는 바로 이 지점에서 출발합니다.

Make나 Zapier 같은 플랫폼은 코딩 없이 **Trigger(시작 이벤트)**와 **Action(처리 동작)**을 시각적으로 연결해 반복 업무를 자동화합니다.

이번 미션에서는 다음 과정을 수행합니다.

1. 동일한 워크플로우를 서로 다른 2개 이상의 자동화 도구로 구현합니다.
2. 구현 결과를 비교하고 분석합니다.
3. 자유 주제로 나만의 자동화 파이프라인을 설계하고 구현합니다.

핵심은 단순히 자동화가 돌아가게 만드는 것이 아닙니다.

- Trigger와 Action의 작동 원리를 이해하기
- 조건 분기를 설계하기
- 도구별 장단점을 근거 있게 비교하기
- 업무에 적합한 도구를 선정하기
- 자동화 흐름을 단계별로 설명하기

이 과정을 마치면 반복 업무를 분석해 자동화 가능 여부를 판단하고, 적합한 도구를 선정해 실제 워크플로우를 구축하는 역량을 갖추게 됩니다.

여기서 쌓은 노코드 자동화 설계 경험은 이후 AI 에이전트 연동이나 코드 기반 자동화로 확장해 나가는 데 탄탄한 발판이 될 것입니다.

# 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 합니다.

## 4.1 공통 요구 사항

두 프로젝트 모두 실제로 동작하는 자동화 워크플로우를 구현해야 합니다.

### 필수 구성

- Trigger 1개 이상
- Action 2개 이상
- 조건 분기(Filter/Router) 1개 이상

### 조건 분기 검증

조건 분기 구조가 포함된 경우, **각 분기 경로가 실제로 1회 이상 실행된 결과**를 확인할 수 있어야 합니다.

즉, 분기 구조만 만들어 놓는 것이 아니라 각 조건에 해당하는 테스트 데이터를 넣고, 모든 경로가 실행되는지 확인해야 합니다.

## 4.2 프로젝트 1 요구 사항

### 구현 조건

- 서로 다른 2개 이상의 자동화 도구를 사용합니다.
- 각 도구에서 동일한 워크플로우 구조를 구현합니다.

### 비교 분석 보고서 필수 항목

- 사용한 도구 이름
- 구현 과정 요약
- 최소 5개 이상의 비교 항목
- 각 도구의 장점과 단점
- 각 도구가 어떤 상황에 적합한지에 대한 의견

### 비교 항목 예시

- UI/UX
- 설정 난이도
- 연동 서비스 범위
- 무료 플랜 범위
- 실행 로그 확인 방식

## 4.3 프로젝트 2 요구 사항

### 구현 조건

- 자동화할 반복 업무 1개를 정의합니다.
- 자동화 도구 1개를 선정합니다.
- 해당 도구를 선정한 이유를 작성합니다.
- Trigger가 발생하면 자동 실행되는 구조를 구현합니다.
- 워크플로우 흐름에 대한 설명을 포함합니다.

# 5. 보너스 과제

보너스 과제는 선택 사항입니다.

## 보너스 1. AI 연동 Action 추가

워크플로우에 생성형 AI를 Action으로 추가합니다.

### 활용 예시

- ChatGPT
- Claude
- 기타 생성형 AI

### 자동 생성할 수 있는 결과 예시

- 텍스트 요약
- 텍스트 분류
- 템플릿 메시지

## 보너스 2. 실패 알림 및 재시도 전략

워크플로우 실행 중 오류가 발생했을 때 실패 상황을 처리합니다.

### 구현 예시

- 이메일로 실패 알림 전송
- 메신저로 실패 알림 전송
- 워크플로우 재시도 또는 재실행
- 저장 실패 시 임시 시트에 적재하는 대체 경로

가능하다면 재시도 또는 대체 경로를 1개 이상 설계합니다.

# 6. 제약 사항

## 6.1 구현 및 동작 제약

- 자동화 도구를 비교 분석하기 위해 도구를 반드시 2개 이상 직접 사용해야 합니다.
- 두 프로젝트 모두 실제로 동작하는 워크플로우여야 합니다.
- 설계 문서만 제출하는 것은 인정되지 않습니다.
- 프로젝트 2는 Trigger가 발생하면 자동으로 실행되어야 합니다.

## 6.2 보안 및 제출물 제약

### 노출 금지 정보

- API Key
- 토큰
- 비밀번호
- 기타 계정 인증 정보

## 6.3 계정 및 연동 환경 리스크 완화

계정 진입장벽이 비교적 낮은 권장 최소 구성은 다음과 같습니다.

```text
Google Sheets + Gmail(또는 Email) + Webhook
```

### 구성 예시 2


무료 플랜으로 완수할 수 있는 조합을 우선 고려합니다.

### 예시

- Make 무료 범위 + Google Sheets
- 자가호스팅 가능한 도구 + 무료 연동 앱

- 사용할 수 있는 무료 대안

# 7. 결과 예시

아래 내용은 정답이 아니라 참고 예시입니다. 실제 내용은 달라도 됩니다.

## 프로젝트 1 예시

### 자동화 도구 비교 구현: Make vs Zapier

**워크플로우**

```text
Google Form 제출
→ 조건 분기(점수 기준)
→ Google Sheets 기록
→ Slack 알림
```

### Make 구현

- Trigger: Google Forms – Watch Responses
- Router: 점수 80점 이상 / 미만 분기
- Action 1: Google Sheets – Add a Row (합격자 시트)
- Action 2: Slack – Send a Message (합격 알림)

### Zapier 구현

- Trigger: Google Forms – New Response in Spreadsheet
- Filter: 점수 80점 이상만 통과
- Action 1: Google Sheets – Create Spreadsheet Row
- Action 2: Slack – Send Channel Message

### 비교 항목 예시

| 비교 항목 | Make | Zapier |
|---|---|---|
| UI/UX | 시각적 노드 기반 | 리스트 기반 |
| 설정 난이도 | 초기 학습 곡선 있음 | 직관적 |
| 연동 서비스 범위 | 광범위하나 세부 커넥터 차이 존재 | 광범위하나 세부 커넥터 차이 존재 |
| 무료 플랜 | 1,000 Ops/월 예시 | 100 Tasks/월 예시 |
| 실행 로그 | 실행 히스토리에서 단계별 데이터 확인 가능 | Task History에서 확인 |

> 무료 플랜 수치는 예시이므로 실제 사용 시점의 플랜을 확인해야 합니다.

## 프로젝트 2 예시

### 자유 주제: 팀 회의록 자동 정리 및 알림

**반복 업무 정의**

매주 회의 후 회의록을 Google Docs에 작성하면 핵심 내용을 요약해 Slack 채널에 공유하는 작업

**선정 도구**

Make

**선정 이유**

시각적 분기 설계가 직관적이고 무료 Ops 범위 내에서 구현할 수 있기 때문입니다.

### 워크플로우 흐름

```text
1. Google Docs에서 새 문서 감지
2. 제목·참석자·결정사항 추출
3. 결정사항 존재 여부 확인
4. Slack에 요약 내용과 담당자 멘션 전송
5. Google Sheets에 회의록 이력 기록
```

### 세부 구성

1. Trigger: Google Docs – Watch Documents (새 문서 감지)
2. Action 1: 텍스트 파싱(제목/참석자/결정사항 추출)
3. Filter: 결정사항이 존재하는 경우에만 다음 단계로 이동
4. Action 2: Slack – Send a Message (요약 내용 + 담당자 멘션)
5. Action 3: Google Sheets – Add a Row (회의록 이력 기록)
