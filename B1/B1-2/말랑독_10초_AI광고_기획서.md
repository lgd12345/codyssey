# 4. 제작 전략 및 버전 구분

## 4.1 초기 씬별 생성 방식의 문제

초기 제작은 Scene 1\~4를 각각 별도 프롬프트로 생성하는 방식이었다. 그러나 각 씬에서 다음 불일치가 발생했다.

* 말랑독의 몸체 비율, 귀 길이, 발 크기, 얼굴 위치가 씬마다 달라짐

* 여자아이의 얼굴형, 헤어스타일, 의상 디테일이 달라짐

* 하늘색의 명도와 재질 표현이 달라짐

* 컷을 연결했을 때 같은 캐릭터가 아니라 서로 다른 캐릭터 모델처럼 보임

따라서 씬별 프롬프트를 각각 제출하는 방식 대신, 캐릭터 고정 묘사와 전체 시간 흐름을 한 프롬프트 안에 넣은 **10초 통합 생성 방식**을 채택하였다. 단 통합생성에도 씬별 특징을 적었다.

## 4.2 말랑독 영상 1버전

* 생성 방식: 10초 통합 Text-to-Video

* 실제 생성 도구: **Google Veo 3.1 Fast**

* 실제 생성 날짜: **2026년 07월 27일**

* 실제 생성 횟수: 3회

* 사용 프롬프트: 본 문서 10장의 **신규 통합 프롬프트**

* 확인 파일: `말랑독_1.mp4`

* 실제 파일 규격: 9.450초, 1280×720, 16:9, 명목 30fps, H.264 영상, AAC 스테레오 44.1kHz 오디오

* 토큰 단가 기록: 초당 약 33,334토큰

* 채택 파일 1개 기준 추산: 약 266,672토큰

* 3회 생성 단순 추산: 약 800,016토큰 (`33,334 × 3`)

* 실제 화면 결과:

  * 걷기 → 점프 → 손 위 착지 → 푸시인 → 윙크 → 아이리스 아웃 → 로고 엔드카드의 전체 흐름이 구현되었다.

  * 여자아이는 갈색 보브컷과 하늘색 후드티를 유지하며 비교적 일관되게 표현되었다.

  * 말랑독은 하늘색과 얼굴 인상은 유지되지만, 낮고 넓은 스트레스볼보다 머리·몸·다리가 구분된 강아지 피규어에 가까워졌다.

  * 약 6.0초의 윙크에서 **화면 오른쪽 눈이 감기고 반대쪽 눈이 크게 열려**, 지정한 `screen-left eye <`와 `other eye unchanged` 조건을 충족하지 못했다.

  * 약 6.7\~7.9초에 얼굴 중심 아이리스 아웃이 작동하고, 약 8.2초부터 `말랑독 / MALLANG DOG` 로고 엔드카드가 나타난다.

  * Gemini TTS 음성은 WAV 파형 대조 결과 약 **6.746\~9.437초**에 배치되어 전체 대사가 10초 안에 재생된다.

* 장점: 10초 이내, 장면 전환과 엔드카드 완성, 여자아이 일관성 양호, TTS 전체 재생

* 보완점: 스트레스볼형 비율, 윙크 눈 방향·형태, 타임코드 압축

## 4.3 말랑독 영상 2버전

* 생성 방식: 10초 통합 Text-to-Video

* 실제 생성 도구: **OpenAI Sora 2**

* 실제 생성 날짜: **2026년 07월 27일**

* 실제 생성 횟수: 4\~7회

* 사용 프롬프트: 기존 기획서 10장의 **기존 통합 마스터 프롬프트**

* 확인 파일: `말랑독_2_16_9.mp4`

* 실제 파일 규격: 11.354초, 1280×720, 16:9, 명목 30fps, H.264 영상, AAC 스테레오 44.1kHz 오디오

* 토큰 단가 기록: 초당 약 33,334토큰

* 채택 파일 1개 기준 추산: 약 400,008**토큰** (`11.354 × 33,334`)

* 7회 생성 단순 추산: 약 **2,000,000토큰** (`11.354 × 33,334 × 4~7`)

* 실제 화면 결과:

  * 04.8초의 여자아이 발견·점프, 4.8초 이후 손 위 착지·클로즈업이 기획 시간 구간과 비교적 유사하다.

  * 초반 말랑독은 낮고 넓은 타원형 스트레스볼에 가깝고 작은 발·꼬리가 보여 제품 콘셉트 적합도가 높다.

  * 손 위 클로즈업에서는 몸체가 세로로 길어져 초반보다 달걀형으로 변하며, 귀 위치와 비율도 달라지는 형태 변형이 있다.

  * 약 7.5\~8.8초에 깨끗한 `<`형 윙크가 보이지만 **화면 오른쪽 눈**에 나타나 프롬프트의 화면 왼쪽 눈 조건과 반대다.

  * 약 9.2\~10.0초에 아이리스 아웃이 나타나지만 원형 마스크 상단에 불규칙한 검은 형태가 섞인다.

  * 약 10.3초부터 `말랑독 / MALLANG DOG` 로고 엔드카드가 시작되며, 원본 전체 재생 기준으로 로고와 브랜드명을 명확하게 인지할 수 있다.

  * Gemini TTS 음성은 WAV 파형 대조 결과 약 **8.646\~11.337초**에 배치되어 원본 전체 재생 기준으로 대사가 완결된다.

* 장점: 제품형 디자인, 씬별 시간 흐름, 점프와 `<`형 윙크의 가독성

* 보완점: 필수 본편 길이에는 사용하지 않는 11.354초 비교본이며, 클로즈업 비율 변형·윙크 눈 방향·불규칙 아이리스가 남아 있음

## 4.4 버전 비교 목적과 채택 방향

같은 브랜드·스토리보드와 유사한 통합 프롬프트를 서로 다른 비디오 모델로 제작하여 품질·제어·속도·비용 차이를 비교하였다.

* 영상 1버전: Google Veo 3.1 Fast + 신규 통합 프롬프트

* 영상 2버전: OpenAI Sora 2 + 기존 통합 프롬프트

* 두 버전은 **모델과 프롬프트가 동시에 다르므로**, 결과 차이를 특정 프롬프트 또는 특정 모델 하나의 영향으로만 단정하지 않는다.

* 과제의 **10초 이내 필수 본편**은 영상 1버전으로 제출한다. 영상 1은 9.450초이며 로고와 TTS가 영상 안에서 완결된다.

* 영상 2버전은 초기 말랑독 디자인 시트의 낮고 넓은 스트레스볼형 제품에 더 가깝고, 낮은 점프와 `<`형 윙크도 기획 의도에 더 근접한다.

* 따라서 영상 2는 **창작 결과의 선호·비교 버전**이자 9:16 보너스 제작의 기준 영상으로 유지한다.

* 보너스 제출물은 영상 2를 세로형 **9:16**으로 리프레이밍한 버전이다. 단순 늘이기가 아니라 제품과 여자아이의 중심 위치, 로고 안전영역을 다시 조정한다.

* 여자아이의 갈색 보브컷, 하늘색 후드티, 베이지 반바지가 유지되는가?

* 걷기 → 점프 → 착지 → 윙크가 순서대로 읽히는가?

* 손가락 왜곡, 중복 캐릭터, 얼굴 변형, 색 변화가 없는가?

* 윙크가 화면 왼쪽 눈의 얇은 `<` 형태로 보이는가?

* 영상 길이가 10초 이내인가?

* 마지막 3\~5초에 브랜드명이 명확하게 노출되는가?

## 6.3 Text-to-Image와 Text-to-Video 선택 이유

### Text-to-Image

* 정지된 캐릭터의 비율, 색, 얼굴, 의상을 세밀하게 확정하기에 적합하다.

* 말랑독과 여자아이의 디자인 기준 이미지를 만드는 단계에 사용한다.

* 움직임의 시간적 연속성을 생성할 수 없으므로 최종 광고 영상 제작에는 단독으로 충분하지 않다.

### Text-to-Video

* 걷기, 점프, 착지, 윙크와 카메라 이동을 시간 순서로 생성할 수 있다.

* 네이토 API를 이용한 별도 제작 환경에서 이미지 입력 기능을 사용할 수 없었으므로 이미지 레퍼런스를 사용하지 않고, 동일한 캐릭터 묘사를 통합 프롬프트 안에서 반복·고정했다.

* **씬별Text-to-Video생성 시 외형 불일치가 커서, 시간 코드가 포함된 통합 Text-to-Video 방식을 최종 선택했다.​**

* 동일 프로젝트를 Veo 3.1 Fast와 Sora 2로 각각 제작해 모델별 결과 차이를 비교했다.

## 7.4 일관성 제어 방법

* 통합 프롬프트의 앞부분에 말랑독과 여자아이의 전체 디자인을 한 번에 명시한다.

* `exact same design throughout`, `keep her design consistent`, `stable character identity`를 사용한다.

* 시간 구간별 행동만 바꾸고 캐릭터 묘사는 변경하지 않는다.

* 카메라 동작을 구간별로 한 가지씩 제한한다.

* 생성된 영상은 후편집에서 색온도, 노출, 채도, 크롭을 통일한다.

* 정확한 로고와 한글은 생성하지 않고 편집에서 삽입한다.

## 7.5 Seed 또는 고정 파라미터 기록

**Seed**는 생성형 모델이 난수를 시작하는 기준값으로, 같은 프롬프트와 설정에서 유사한 결과를 다시 얻기 위해 사용하는 재현 제어값이다. 이번 제작에서는 사용자가 Seed를 별도로 입력하거나 고정하지 않았고, 네이토 API 연동 환경에서도 사용자에게 Seed 또는 동등한 고정 파라미터 설정이 노출되지 않았다. 따라서 기록은 다음과 같이 통일한다.

* 사용자 지정 Seed: **미사용**

* 네이토 API 환경의 사용자 Seed·고정 파라미터 설정: **제공되지 않음 또는 확인 불가**

* 일관성 확보 방식: 디자인 시트를 프롬프트·검수 기준으로 사용, 통합 프롬프트, 동일 캐릭터 묘사 반복, CapCut 후편집

8. **최종 검수**길이, 프레임, 블랙 엔딩, 오디오 싱크, 브랜드 노출 시간을 확인한다.

# 16. 크레딧·대기열 대응 전략

## 16.1 기본 전략

* 디자인 이미지를 먼저 확정한 후 비디오 생성에 들어간다.

* 씬별 4회 이상 생성보다 통합 프롬프트 1\~2회 생성을 우선한다.

* 한 번의 재생성에서는 외형, 동작, 카메라 중 한 요소만 수정한다.

* 영상 1버전과 2버전 비교 후 더 안정적인 결과를 채택한다.

* 로고, 한글, 아이리스 아웃처럼 편집으로 정확히 처리 가능한 요소는 생성 크레딧을 추가로 사용하지 않는다.

## 16.2 크레딧 부족 시 대응

1. 4개 씬을 유지하되 통합 생성 1회만 실시한다.

2. 점프나 손 표현이 실패하면 전체를 재생성하기 전에 해당 구간을 짧은 정지·슬로모션·크롭으로 편집 보완한다.

3. 필요한 경우 Scene 1과 Scene 2를 하나의 짧은 움직임으로 축약한다.

4. 윙크가 실패하면 마지막 제품 클로즈업 정지 이미지를 사용하고 편집에서 눈 모양과 아이리스 아웃을 보완한다.

5. 기존 Gemini TTS를 재사용하고, 추가 BGM·SFX 생성은 생략하거나 최소화한다.

## 16.3 대기열·플랜 제한 시 대응

* 주 비디오 도구의 대기열이 길면 대체 비디오 도구로 동일 통합 프롬프트를 테스트한다.

* 10초 생성을 지원하지 않으면 5초 2개로 분할하되, 동일한 캐릭터 묘사와 색상·카메라 기준을 반복한다.

* 해상도가 낮으면 720p 이상으로 생성한 뒤 최종 타임라인에서 업스케일·샤프닝을 최소한으로 적용한다.

# 18. 평가 인터뷰 대비 답변

## 18.1 “기획 → 생성 → 검수 → 편집/통합”을 어떤 순서로 설계했는가?

먼저 브랜드 타겟·톤앤매너·USP와 10초 서사를 정하고 ChatGPT 5.6으로 말랑독·말랑이 디자인 시트와 로고를 확정했다. 이후 씬별 생성의 캐릭터 불일치를 확인해 통합 Text-to-Video로 전환하고, 신규 프롬프트는 Veo 3.1 Fast, 기존 프롬프트는 Sora 2로 제작했다. 결과를 외형·동작·길이·브랜드 구간으로 검수한 뒤 CapCut에서 컷, 로고, Gemini TTS 내레이션을 통합했다.

## 18.2 크레딧·대기열을 고려해 씬 수와 생성 횟수를 어떻게 설계했는가?

10초 광고를 4개 의미 구간으로 설계했지만 실제 출력은 통합 영상 방식으로 제작했다. Google Veo 3.1 Fast는 3회, OpenAI Sora 2는 7회로 총 10회 생성했으며, 반복 결과 중 제품 형태와 움직임이 가장 적합한 파일을 비교했다. 이후 영상 1은 10초 이내 필수 본편으로, 영상 2는 디자인 선호·비교 및 보너스 기준본으로 역할을 나누고 추가 영상 재생성을 중단했다.

## 18.3 톤앤매너와 에셋 규격을 어떻게 표준화했는가?

두 생성 원본은 모두 16:9, 1280×720, 30fps로 출력되어 CapCut 타임라인을 해당 실제 규격에 맞췄다. 제출 시 720p 기준을 충족하며 필요할 때만 1080p로 출력한다. 색감은 파스텔 하늘색과 크림색, 따뜻한 확산광, 얕은 심도, 부드러운 소프트 러버 재질을 공통 기준으로 사용한다.

## 18.4 결과 파일을 어떻게 재사용 가능하게 정리했는가?

기획, 디자인, 영상 버전, 오디오, 편집, 최종 출력 폴더를 분리했다. 파일명에는 자산 종류, 프롬프트 버전, 생성 횟수, 최종 여부를 포함한다. 원본을 덮어쓰지 않아 어떤 프롬프트와 생성 결과가 채택되었는지 추적할 수 있다.

## 18.5 Text-to-Image와 Text-to-Video의 차이와 선택 기준은 무엇인가?

Text-to-Image는 한 프레임의 디자인·색·비율을 세밀하게 확정하는 데 적합하므로 캐릭터 디자인 시트에 사용했다. Text-to-Video는 걷기·점프·착지·윙크와 카메라 이동을 시간 순서로 생성할 수 있어 최종 광고에 사용했다. 본 프로젝트에서는 동작이 핵심이므로 Text-to-Video가 필요했다. 영상 생성은 네이토 API를 이용한 별도 환경에서 수행했으며, 해당 환경은 이미지 입력을 지원하지 않아 이미지 레퍼런스를 사용하지 못했다. 따라서 통합 프롬프트와 반복된 캐릭터 묘사로 일관성을 보완했다.

## 18.6 도구를 선택할 때 품질·제어·속도·비용 중 무엇을 우선했는가?

가장 우선한 것은 품질이고 그 중에 캐릭터 일관성과 제어 가능성이다. 그다음으로 소프트 러버 재질과 손·점프 품질을 비교했다. 비용 측면에서는 Veo 3.1 Fast와 Sora 2 모두 초당 약 33,334토큰으로 기록되었고, 실제 생성은 Google 3회·OpenAI 7회였다. 채택 파일 길이와 횟수를 단순 곱하면 영상 생성 약 3,594,339토큰으로 추산된다. 짧은 TTS는 약 896토큰을 사용해 메시지를 보완했으며, 디자인과 로고는 ChatGPT 유료 기본 구독 범위에서 제작했다.

## 18.7 프롬프트 A→B로 바꾸며 무엇이 달라졌는가?

A는 씬별 독립 프롬프트였고 B는 캐릭터 고정 묘사와 전체 시간 코드를 묶은 통합 프롬프트였다. 통합본은 컷 간 외형 불일치를 줄였다. 추가 비교에서 신규 프롬프트를 Veo 3.1 Fast, 기존 프롬프트를 Sora 2에 사용했다. Sora 결과는 스트레스볼형 디자인과 낮은 점프가 우수했고, Veo 결과는 10초 내 엔드카드와 TTS 완결성이 우수했다. 모델과 프롬프트를 동시에 변경했으므로 원인을 단일 변수로 단정하지 않는다.

## 18.8 캐릭터·스타일 일관성을 위해 어떤 제어 방법을 사용했는가?

ChatGPT 5.6으로 제작한 턴어라운드·디테일 디자인 시트를 시각 기준으로 두고, 통합 프롬프트에 `exact same design throughout`, `keep her design consistent`, `stable character identity`를 사용했다. 동작은 시간 구간별로 하나씩 제한했다. 생성 영상의 형태 오차는 검수표에 기록하고, 정확한 로고와 브랜드 메시지는 CapCut에서 ChatGPT 로고와 Gemini TTS로 통합했다.

## 18.9 서로 다른 도구 결과물의 해상도·비율·색감·톤을 어떻게 보정하는가?

먼저 실제 원본과 같은 1280×720, 30fps, 16:9 타임라인으로 규격을 맞춘다. 필요할 때만 최종 출력에서 1080p로 업스케일한다. 이후 따뜻한 화이트밸런스와 파스텔 하늘색 제품 색상을 기준으로 노출·채도·색온도를 조정한다. TTS는 전체 2.691초를 보존하고, 로고는 동일한 안전영역과 정렬 기준으로 배치한다.

## 18.10 같은 스토리보드를 다른 도구로 만들면 무엇이 가장 달라지는가?

* 품질: 재질, 손, 얼굴, 모션의 자연스러움이 달라진다.

* 제어: 시간 코드, 네거티브 프롬프트, 캐릭터 고정 기능의 반영 정도가 달라진다.

* 속도: 생성 대기열과 10초 출력 시간이 달라진다.

* 비용: 1회 생성 크레딧과 재생성 비용이 달라진다.

실제 비교에서 Veo 3.1 Fast는 엔딩 타이밍과 인물 안정성이 상대적으로 좋았고, Sora 2는 스트레스볼형 제품과 낮은 점프가 상대적으로 좋았다. 두 모델의 토큰 단가는 동일하게 기록되었으므로 결과 품질과 편집 가능성이 채택의 핵심이었다. 초기 말랑독 디자인과 제품 형태의 유사도는 Sora 2의 영상 2가 높았지만, 10초 이내 필수 제출 조건은 Veo 3.1 Fast의 영상 1로 충족했다. 영상 2는 비교와 9:16 보너스 제작에 활용한다.

## 18.11 영상 생성 크레딧이 부족해지면 어떻게 바꾸는가?

4개 의미 구간은 유지하되 통합 영상 1회만 생성한다. 실패 구간은 전체 재생성보다 정지 프레임, 짧은 줌, 속도 조절, 마스킹으로 보완한다. 제대로 나오지 않은 윙크·아이리스·로고는 CapCut에서 처리하고, 이미 생성한 Gemini TTS를 재사용한다. 필요하면 걷기와 발견을 한 구간으로 합쳐 생성 난도를 낮춘다.

## 18.12 60초 버전을 15초로 줄여야 한다면 무엇을 유지·삭제하는가?

유지할 핵심은 제품 등장, 사용자를 향한 이동, 손 위 착지, 시그니처 윙크, 브랜드 엔딩이다. 반복되는 이동 장면, 여러 반응 컷, 제품 기능의 중복 설명은 삭제한다. 15초 구조는 `3초 등장 → 4초 접근·점프 → 4초 손 위 교감 → 4초 윙크·브랜드`로 재구성해 “손안에서 만나는 말랑한 강아지” 메시지를 한 번만 명확하게 전달한다.
