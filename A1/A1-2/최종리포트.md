# A1-2 Python 응용: API 활용 국내 여행지 추천 프로그램 개발

사용자가 여행 날짜를 입력하면 LLM이 해당 시기에 방문하기 좋은 국내 여행지를 추천하고, 추천된 지역을 Kakao Local API의 검색어로 연결하여 맛집을 검색한 뒤 최종 Markdown 여행 리포트를 생성하는 CLI 프로그램입니다.

프로젝트에서는 단순히 API를 각각 호출하는 것이 아니라, **한 API의 출력을 다음 API의 입력으로 연결하는 흐름**을 구현했습니다.

```text
날짜 입력
   ↓
LLM 여행지 추천
   ↓
JSON 파싱 및 검증
   ↓
recommended_city
   ↓
Kakao 맛집 검색
   ↓
Raw JSON 저장
   ↓
LLM 최종 리포트 생성
```

## 4. 실행 방법과 날짜 검증

과제 필수 옵션인 `-date`를 지원하며 `--date`도 별칭으로 사용할 수 있습니다.

```powershell
python travel_planner.py -date "2027-03-12"
```

또는

```powershell
python travel_planner.py --date "2027-03-12"
```

### 날짜 검증

`argparse`와 `datetime.strptime()`을 사용하여 입력값이 실제 존재하는 날짜인지 확인하고, 내부에서는 `YYYY-MM-DD` 형식으로 정규화합니다.

**구현**

```python
def validate_date(value):
    try:
        parsed_date = datetime.strptime(value, "%Y-%m-%d")
        return parsed_date.strftime("%Y-%m-%d")
    except ValueError:
        raise argparse.ArgumentTypeError(
            "날짜는 YYYY-MM-DD 형식의 올바른 날짜여야 합니다."
        )
```

`-date`는 필수 옵션으로 설정했습니다.

```python
parser.add_argument(
    "-date",
    "--date",
    dest="date",
    required=True,
    type=validate_date,
    metavar="YYYY-MM-DD"
)
```

**테스트**

다음 상황을 각각 실행했습니다.

```text
2026/10/7
2026-02-30
-date 옵션 미입력
```

**확인 결과**

잘못된 형식, 존재하지 않는 날짜, 필수 옵션 누락 시 `argparse`가 사용법과 오류 메시지를 출력하고 API 호출 전에 종료되는 것을 확인했습니다.

## 6. 1차 LLM 추천과 JSON 검증

첫 번째 Naito API 호출에서는 여행 날짜를 전달하고 다음 4개 필드를 가진 JSON을 요청합니다.

```json
{
  "recommended_city": "전라남도 광양시",
  "weather": "해당 시기의 날씨 특징",
  "events": [
    "행사 또는 축제"
  ],
  "reason": "추천 이유"
}
```

자유 텍스트 대신 JSON을 사용하는 이유는 다음 단계에서 필요한 값을 프로그램이 안정적으로 추출하기 위해서입니다.

```python
city = recommendation["recommended_city"]
```

### 스키마 검증

LLM 응답은 `json.loads()`가 성공했다고 바로 사용하지 않고 `validate_recommendation()`에서 다시 검증합니다.

**구현**

```python
required_fields = {
    "recommended_city": str,
    "weather": str,
    "events": list,
    "reason": str
}

if set(data.keys()) != set(required_fields.keys()):
    return False

for key, expected_type in required_fields.items():
    if not isinstance(data[key], expected_type):
        return False
```

추가로 다음 내용을 확인합니다.

* 문자열 값이 비어 있지 않은지

* `events`가 1\~3개인지

* `events` 내부 값이 문자열인지

* 추천 지역이 대한민국 행정구역인지

국내 지역 여부는 다음과 같이 검사합니다.

```python
if not data["recommended_city"].startswith(KOREA_REGIONS):
    return False
```

따라서 **JSON 형식뿐 아니라 프로그램에서 사용할 수 있는 데이터인지까지 검증한 뒤 다음 API로 전달**합니다.

## 7. JSON 실패 재시도와 프롬프트 개선

첫 LLM 응답이 JSON 파싱 또는 스키마 검증에 실패하면 최대 1회만 다시 요청합니다.

**구현**

```python
recommendation = parse_recommendation(recommendation_text)

if recommendation is not None:
    return recommendation

print("1차 추천 JSON 검증 실패 - 재시도합니다.")

retry_text = retry_travel_recommendation(api_key, date)
recommendation = parse_recommendation(retry_text)
```

두 번째 요청에서도 실패하면 `errors`에 기록합니다.

```python
errors.append({
    "step": "recommendation",
    "type": "JSON_PARSE_ERROR",
    "message": "LLM JSON parsing or schema validation failed after one retry"
})
```

재시도까지 실패하면 Kakao 검색에 사용할 정상적인 지역 정보가 없으므로 추천 단계에서 실행을 종료합니다.

### 실제 재시도 테스트

**테스트**

재시도 코드가 실제 실행되는지 확인하기 위해 테스트 중에만 첫 번째 LLM 응답을 다음처럼 임시 변경했습니다.

```python
recommendation_text = "잘못된 JSON"
```

**확인 결과**

```text
[1/3] 1차 추천 생성 중(LLM)...
1차 추천 JSON 검증 실패 - 재시도합니다.
1차 추천 JSON 검증 완료
추천 지역: 강원특별자치도 태백시
```

재시도가 한 번 수행되고 정상 데이터가 반환되면 다음 단계로 진행하는 것을 확인했습니다. 테스트용 코드는 이후 삭제했습니다.

### 개발 중 개선

재시도 테스트 과정에서 JSON 구조는 정상이지만 다음과 같은 해외 지역이 반환된 경우가 있었습니다.

```text
삿포로시 주오구
```

기존의 키와 타입 검사만으로는 이를 걸러낼 수 없었기 때문에 다음을 보완했습니다.

1. 프롬프트에 대한민국 국내 행정구역 조건 추가

2. `KOREA_REGIONS`를 이용한 국내 지역 검증 추가

또한 초기 `events` 결과에 `산책`, `감상`, `탐방`과 같은 일반 관광 활동이 포함되는 경우가 있어 프롬프트를 수정했습니다.

```text
events에는 실제 행사 또는 축제 이름만 작성
산책, 감상, 탐방 같은 일반 여행 활동은 제외
```

이후에는 행사/축제 형태의 데이터를 반환하도록 개선했습니다.

## 8. Kakao Local API 맛집 검색

검증된 LLM 결과의 `recommended_city`를 Kakao Local API의 입력으로 직접 사용합니다.

**API 연결**

```python
restaurants = search_restaurants(
    kakao_api_key,
    recommendation["recommended_city"],
    errors
)
```

Kakao 검색어는 다음과 같이 구성합니다.

```python
params = {
    "query": f"{city} 맛집",
    "size": 5
}
```

즉,

```text
LLM 결과
recommended_city = "전라남도 광양시"
        ↓
Kakao 검색어
"전라남도 광양시 맛집"
```

형태로 **첫 번째 API의 결과를 두 번째 API의 실제 입력값으로 연결**했습니다.

### 공통 맛집 데이터 구조

Kakao의 원본 응답을 프로그램 전체에서 직접 사용하지 않고 `search_restaurants()` 안에서 다음 구조로 변환합니다.

```python
restaurants.append({
    "name": place.get("place_name", ""),
    "address": (
        place.get("road_address_name")
        or place.get("address_name", "")
    ),
    "category": place.get("category_name", ""),
    "url": place.get("place_url", ""),
    "lng": float(place["x"]) if place.get("x") else None,
    "lat": float(place["y"]) if place.get("y") else None
})
```

이 구조를 사용하면 Kakao를 Naver 등의 다른 장소 API로 변경할 경우에도 주로 다음 부분만 수정하면 됩니다.

```text
인증 방식
요청 URL / 파라미터
외부 API 응답 → 공통 restaurant 구조 변환
```

Raw JSON 저장이나 최종 리포트 생성 부분은 그대로 사용할 수 있습니다.

## 9. 오류 처리와 테스트

외부 API는 일부 단계가 실패해도 가능한 데이터를 최대한 유지하도록 처리했습니다.

`errors`는 다음 구조로 관리합니다.

```json
{
  "step": "place_search",
  "type": "AUTH_ERROR",
  "message": "HTTP 401"
}
```

### 9.1 API 키 누락

**구현**

`NAITO_API_KEY`, `KAKAO_API_KEY` 중 하나라도 없으면 API 호출 전에 즉시 종료합니다.

**테스트**

환경변수 이름을 임시 변경하여 Kakao API 키가 없는 상태를 만들었습니다.

**확인 결과**

```text
API 키가 설정되지 않았습니다.
누락된 키: KAKAO_API_KEY
.env 파일에 해당 API 키를 설정해주세요.
```

API 요청 전에 정상적으로 종료되는 것을 확인한 뒤 원래 설정으로 복구했습니다.

### 9.2 Kakao 401 / 403 인증 오류

Kakao API의 인증 오류는 프로그램 전체를 종료하지 않고 `AUTH_ERROR`로 기록합니다.

**구현**

```python
if status_code in (401, 403):
    error_type = "AUTH_ERROR"
elif status_code == 429:
    error_type = "QUOTA_ERROR"
else:
    error_type = "API_ERROR"
```

**테스트**

테스트 중에만 Kakao API 키를 잘못된 값으로 변경했습니다.

```text
KAKAO_API_KEY=TEST_INVALID_KEY
```

키 자체는 존재하므로 프로그램의 키 존재 검사는 통과하지만 실제 Kakao 요청에서는 HTTP 401이 발생하도록 만들었습니다.

**확인 결과**

Raw JSON의 오류 정보가 다음과 같이 기록되었습니다.

```json
"errors": [
  {
    "step": "place_search",
    "type": "AUTH_ERROR",
    "message": "HTTP 401"
  }
]
```

동시에 `restaurants=[]`로 처리되어 프로그램이 중단되지 않고 최종 Markdown 리포트 생성까지 진행했습니다.

테스트가 끝난 뒤 API 키는 정상 값으로 복구했습니다.

401/403이 발생하면 다음 순서로 확인할 수 있습니다.

```text
API 키
→ 환경변수 이름
→ Authorization Header 형식
→ API 사용 권한
→ 플랫폼/도메인 제한
→ 요청 URL과 endpoint
```

### 9.3 검색 결과 0건

Kakao 요청 자체는 성공했지만 검색 결과가 없는 경우도 별도로 처리합니다.

**구현**

```python
if not documents:
    errors.append({
        "step": "place_search",
        "type": "EMPTY_RESULT",
        "message": f"0 results for query={city} 맛집"
    })
    return []
```

**테스트**

API 키와 요청 URL은 정상 상태로 유지하고, 검색어만 테스트용으로 존재하기 어려운 임의 문자열로 잠시 변경했습니다.

이 방법으로 인증 오류가 아닌 **정상 API 응답 + 검색 결과 0건** 상황을 만들었습니다.

**확인 결과**

```text
맛집 검색 결과 없음 - 다음 단계로 진행합니다.
```

Raw JSON에는 `restaurants=[]`와 `EMPTY_RESULT`가 기록되었고, 최종 리포트까지 계속 생성되었습니다.

최종 리포트의 맛집 항목에는 `데이터 없음`이 표시됩니다.

테스트 후 검색어는 다시 원래 코드인 다음 형태로 복구했습니다.

```python
"query": f"{city} 맛집"
```

### 9.4 기타 오류

Kakao 요청 중 네트워크 오류가 발생하면 `RequestException`을 처리하여 `errors`에 저장하고 빈 맛집 목록을 반환합니다.

응답 JSON 자체를 처리할 수 없는 경우에는 `JSON_PARSE_ERROR`로 기록합니다.

HTTP 429는 `QUOTA_ERROR`로 구분합니다.

반면 Naito API는 추천과 최종 리포트 생성을 담당하는 핵심 API이므로 인증 오류, 요청 한도 초과, 네트워크 오류 등이 발생하면 사용자에게 원인을 출력하고 종료하도록 처리했습니다.

## 10. 최종 여행 리포트와 결과 저장

1차 추천 결과, 맛집 목록, 오류 정보를 Raw JSON으로 먼저 저장합니다.

**Raw JSON 구조**

```json
{
  "recommendation": {},
  "restaurants": [],
  "errors": []
}
```

저장 코드는 다음과 같습니다.

```python
raw_data = {
    "recommendation": recommendation,
    "restaurants": restaurants,
    "errors": errors
}

file_path = f"results/{date}_raw.json"
```

그 후 이 데이터를 다시 Naito API에 전달하여 최종 Markdown 리포트를 생성합니다.

최종 리포트에는 다음 항목을 포함하도록 프롬프트를 구성했습니다.

```text
추천 지역
추천 이유
날씨 요약
행사/축제
맛집 추천
1일 일정 제안
  - 오전
  - 오후
  - 저녁
오류 요약
```

맛집 목록이 비어 있으면 `데이터 없음`, 오류가 없으면 오류 요약에 `없음`을 표시하도록 했습니다.

현재 제출용 결과는 다음 두 파일입니다.

```text
results/
├── 2027-03-12_raw.json
└── 2027-03-12_travel_plan.md
```

## 11. 결과 캐싱

같은 날짜를 반복 실행하면 동일한 LLM 추천과 Kakao 장소 검색에 API 비용이 다시 발생합니다.

이를 줄이기 위해 첫 번째 LLM 호출 전에 동일한 날짜의 Raw JSON이 있는지 확인합니다.

**구현**

```python
cached_data = load_cached_data(args.date)

if cached_data is not None:
    recommendation = cached_data["recommendation"]
    restaurants = cached_data["restaurants"]
    errors = cached_data["errors"]
```

캐시 파일이 있더라도 그대로 신뢰하지 않고 추천 데이터 스키마와 `restaurants`, `errors`의 타입을 다시 확인합니다.

캐시 파일이 없거나 JSON이 손상된 경우에는 정상적인 API 호출 흐름으로 돌아갑니다.

**테스트**

이미 정상 실행한 날짜를 다시 입력했습니다.

**확인 결과**

```text
기존 결과 캐시를 발견했습니다.
추천 지역: 경상남도 진주시
기존 맛집 데이터 5곳 사용

[3/3] 최종 리포트 생성 중(LLM)...
```

첫 번째 LLM 추천과 Kakao 검색이 생략되고 기존 Raw JSON의 추천 및 맛집 데이터가 재사용되는 것을 확인했습니다.

## 12. GET / POST 사용과 검색어 보정

### GET과 POST

Naito와 Kakao API는 목적에 맞게 서로 다른 HTTP 메서드를 사용했습니다.

| API         | 메서드    | 사용 이유                                     |
| ----------- | ------ | ----------------------------------------- |
| Naito LLM   | `POST` | 모델명과 메시지를 JSON Body로 보내 새로운 추천 또는 리포트를 생성 |
| Kakao Local | `GET`  | 이미 존재하는 장소 데이터를 검색어와 함께 조회                |

Naito 호출:

```python
response = requests.post(
    NAITO_URL,
    headers=headers,
    json=data,
    timeout=30
)
```

Kakao 호출:

```python
response = requests.get(
    KAKAO_LOCAL_URL,
    headers=headers,
    params=params,
    timeout=30
)
```

### 추천 지역이 너무 넓을 때

`경기도`, `경상남도`처럼 광역 단위만 반환되면 맛집 검색 범위가 너무 넓어질 수 있습니다.

현재 구현에서는 LLM 프롬프트에 **광역자치단체명을 포함한 시/군/구 수준의 구체적인 지역**을 요청하고 있습니다.

예:

```text
경상남도
```

보다

```text
경상남도 진주시
```

형태를 사용합니다.

또한 Kakao 검색 직전에 다음과 같이 검색어를 보정합니다.

```python
f"{recommended_city} 맛집"
```

향후 지역 표현이 더 다양해진다면 별도 alias 정규화 함수를 추가하여 `제주도`, `제주`, `제주특별자치도` 같은 표현을 통일할 수 있습니다.

## 13. API 키 보안

API 키는 코드에 직접 작성하지 않고 `.env` 또는 환경변수로 분리했습니다.

이렇게 관리하는 이유는 다음과 같습니다.

* GitHub 등의 저장소에 API 키가 노출되는 것을 방지

* API 키가 변경되어도 Python 코드를 수정할 필요가 없음

* 다른 사람이 키를 사용하여 쿼터나 비용을 소모하는 상황 방지

실제 `.env`가 Git에서 제외되는지도 확인했습니다.

```powershell
git check-ignore -v travel_planner/.env
```

확인 결과:

```text
.gitignore:224:.env     travel_planner/.env
```

따라서 실제 API 키가 포함된 `.env`는 Git 추적 대상에서 제외됩니다.

실제 API 키는 다음 자료에도 포함하지 않습니다.

```text
Python 코드
README
Raw JSON
Markdown 리포트
터미널 로그
제출 스크린샷
```

## 14. 구현 및 테스트 요약

| 항목            | 구현 / 테스트 결과                                |
| ------------- | ------------------------------------------ |
| `-date` 필수 옵션 | `argparse`로 구현, `--date`도 지원               |
| 날짜 검증         | 잘못된 형식, 존재하지 않는 날짜, 옵션 누락 확인               |
| API 키 누락      | API 요청 전에 즉시 종료 확인                         |
| Naito LLM 연결  | `POST` 요청 정상 동작                            |
| 1차 JSON       | 4개 필수 키와 타입 검증                             |
| 국내 지역 검증      | 해외 지역 추천을 검증 단계에서 차단                       |
| JSON 실패       | 재시도 최대 1회 동작 확인                            |
| API 간 연결      | `recommended_city`를 Kakao 검색어로 직접 사용       |
| Kakao 검색      | `GET`으로 최대 맛집 5곳 검색                        |
| Kakao 401     | `AUTH_ERROR` 기록 후 리포트 계속 생성                |
| 검색 결과 0건      | `EMPTY_RESULT`, `restaurants=[]` 후 계속 진행   |
| 오류 관리         | `step`, `type`, `message` 구조로 `errors`에 누적 |
| Raw JSON      | `results/{date}_raw.json` 생성               |
| Markdown      | `results/{date}_travel_plan.md` 생성         |
| 1일 일정         | 오전 / 오후 / 저녁 수준으로 생성                       |
| 결과 캐싱         | 동일 날짜 Raw JSON 재사용 확인                      |
| API 키 보안      | `.env` Git 제외 확인                           |

## 15. 최종 실행 결과

최종 코드에서 `2027-03-12`를 입력해 정상 실행을 확인했습니다.

```text
입력한 여행 날짜: 2027-03-12
API 키 설정 확인 완료

[1/3] 1차 추천 생성 중(LLM)...
1차 추천 JSON 검증 완료
추천 지역: 전라남도 광양시

[2/3] 맛집 검색 중(Kakao Local API)...
맛집 5곳 검색 완료

원본 데이터 저장 완료: results/2027-03-12_raw.json

[3/3] 최종 리포트 생성 중(LLM)...
최종 리포트 생성 완료
완료! results/2027-03-12_travel_plan.md 를 확인하세요.
```

최종적으로 다음 두 결과 파일을 제출용으로 유지했습니다.

```text
2027-03-12_raw.json
2027-03-12_travel_plan.md
```

이 프로그램은 **CLI 입력 → 구조화된 LLM 추천 → 장소 API 연결 → 부분 실패 처리 → 결과 저장 → 최종 리포트 생성**의 전체 API 연동 흐름을 구현하고, 반복 실행 시에는 기존 데이터를 재사용하여 불필요한 API 호출도 줄이도록 구성했습니다.
