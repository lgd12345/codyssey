# 1. 미션 소개

GenAI 기초부터 멀티모달 콘텐츠 제작, 노코드 자동화까지 미션을 수행하면서 프롬프트가 수십 개씩 쌓였을 것입니다.

텍스트 생성을 위한 정교한 지시문부터 이미지 생성용 키워드, 복잡한 페르소나 설계안까지 다양한 프롬프트를 만들었지만, 필요할 때마다 “그때 그 프롬프트 어디 갔지?” 하며 메모장, 노션, 메신저 등을 뒤져야 했다면 이제 이를 체계적으로 관리할 공간이 필요합니다.

이번 미션에서는 흩어진 프롬프트를 한곳에서 관리할 수 있는 **프롬프트 관리 프로그램**을 Python으로 직접 구현합니다.

단순히 변수, 조건문, 반복문 같은 기초 문법을 외우는 것이 목적이 아닙니다. 직접 프로그램을 만들면서 각각의 문법 요소가 실제 프로그램 안에서 어떻게 연결되고 동작하는지 경험하는 것이 핵심입니다.

구현할 주요 기능은 다음과 같습니다.

- 프롬프트를 카테고리별로 분류
- 키워드로 프롬프트 검색
- 프롬프트 상세 내용 확인
- 자주 사용하는 프롬프트 즐겨찾기
- 프로그램 실행 중 추가한 데이터 유지

동시에 Git을 사용하여 코드의 변경 이력을 관리합니다.

기능 하나를 완성할 때마다 커밋하고, 별도의 브랜치에서 기능을 개발한 뒤 `main` 브랜치로 병합합니다. 마지막에는 GitHub에 저장소를 올려 내가 만든 프로그램과 개발 과정을 외부에서 확인할 수 있도록 합니다.

이 미션의 최종 목표는 단순히 Python 프로그램 하나를 만드는 것이 아니라,

```text
아이디어 구상 → 코드 구현 → 기능 분리 → 버전 관리 → GitHub 공개
```

의 전체 개발 흐름을 직접 경험하는 것입니다.

# 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 합니다.

## 4.1 개발 환경

### VSCode 설정

- VSCode에 Python 확장(Extension)을 설치합니다.
- Korean Language Pack 설치는 선택 사항입니다.

### Python 확인

터미널에서 Python 버전을 확인합니다.

```bash
python --version
```

또는 환경에 따라 다음 명령어를 사용할 수 있습니다.

```bash
python3 --version
```

사용 버전은 **Python 3.10 이상**이어야 합니다.

간단한 Python 코드도 작성하고 실행합니다.

```python
print("Hello")
```

### Git 설정

Git 버전을 확인합니다.

```bash
git --version
```

Git 사용자 이름과 이메일을 설정합니다.

```bash
git config --global user.name "사용자 이름"
git config --global user.email "사용자 이메일"
```

기본 브랜치 이름을 `main`으로 설정합니다.

```bash
git config --global init.defaultBranch main
```

### GitHub 연결

- VSCode에서 GitHub 계정으로 로그인합니다.
- GitHub 연동이 정상적으로 되었는지 확인합니다.

## 4.2 Git 저장소 설정 및 초기화

### GitHub 저장소 생성

GitHub에 새로운 저장소를 생성합니다.

### 로컬 프로젝트 초기화

프로젝트 폴더를 만들고 Git 저장소를 초기화합니다.

```bash
git init
```

원격 저장소를 연결합니다.

첫 번째 커밋과 푸시를 수행합니다.

```bash
git add .
git commit -m "프로젝트 초기 설정"
git push
```

### 추가 파일

`.gitignore` 파일을 생성하여 불필요한 파일이 Git에 포함되지 않도록 합니다.

`README.md` 파일을 만들고 프로젝트 제목을 작성합니다.

### clone 실습

공개된 샘플 GitHub 저장소 1개를 `clone`으로 내려받습니다.

```bash
git clone <저장소 URL>
```

clone 후 다음 내용을 확인합니다.

- 폴더 구조
- Git 로그

확인이 끝난 저장소는 삭제해도 됩니다.

## 4.3 프로그램 실행 및 메뉴

프로그램 실행 시 메뉴가 출력되어야 합니다.

## 4.4 기본 프롬프트 데이터

프로그램이 시작되면 이전 미션에서 작성한 프롬프트가 **최소 3개 이상** 등록되어 있어야 합니다.

프롬프트 데이터는 **리스트와 딕셔너리**를 사용하여 저장합니다.

각 프롬프트에는 다음 정보가 포함되어야 합니다.

| 필드 | 내용 |
|---|---|
| 제목 | 프롬프트 이름 |
| 내용 | 실제 프롬프트 전문 |
| 카테고리 | 프롬프트 종류 |
| 즐겨찾기 여부 | `True` 또는 `False` |

### 카테고리 예시

- 텍스트 생성
- 이미지 생성
- 영상 생성
- 페르소나
- 자동화
- 기타

### 데이터 구조 예시

```python
prompts = [
    {
        "title": "블로그 글 작성 도우미",
        "content": "당신은 10년 경력의 전문 블로거입니다...",
        "category": "텍스트 생성",
        "favorite": True
    },
    {
        "title": "제품 썸네일 생성",
        "content": "다음 제품의 매력적인 썸네일 이미지를 생성해주세요...",
        "category": "이미지 생성",
        "favorite": False
    }
]
```

## 4.5 프롬프트 추가

새로운 프롬프트를 등록할 수 있어야 합니다.

### 입력 항목

1. 제목
2. 내용
3. 카테고리

### 입력 검증

제목, 내용 등 필수 입력값이 비어 있다면 바로 저장하지 않고 다시 입력을 요청해야 합니다.

### 카테고리

카테고리는 다음 두 방식 중 하나로 입력할 수 있도록 합니다.

- 미리 정의된 카테고리 목록에서 선택
- 사용자가 직접 입력

### 저장 규칙

추가된 프롬프트는 기존 프롬프트 리스트에 저장됩니다.

```text
새 프롬프트 입력
↓
입력값 검증
↓
카테고리 선택
↓
리스트에 추가
↓
추가 완료 메시지
```

새 프롬프트의 즐겨찾기 기본값은 다음과 같습니다.

```python
"favorite": False
```

프로그램 실행 중에만 유지되어도 됩니다.

## 4.6 프롬프트 목록 — 브랜치 활용

이 기능은 Git 브랜치를 활용하여 개발해야 합니다.

### Git 작업 조건

1. `main` 이외의 추가 브랜치 생성
2. 해당 브랜치로 이동
3. 프롬프트 목록 기능 구현
4. 기능 완성 후 커밋
5. `main` 브랜치로 이동
6. 작업 브랜치 병합

예시 흐름:

```text
main
 ↓
목록 기능용 브랜치 생성
 ↓
checkout
 ↓
목록 기능 구현
 ↓
commit
 ↓
main으로 checkout
 ↓
merge
```

### 프로그램 기능

저장된 모든 프롬프트를 번호와 함께 출력합니다.

각 항목에는 다음 정보가 보여야 합니다.

- 번호
- 카테고리
- 제목
- 즐겨찾기 여부 `⭐`

프롬프트가 없다면 별도의 안내 메시지를 출력합니다.

사용 가능한 카테고리 목록을 먼저 출력합니다.

```text
카테고리 목록
↓
사용자 선택
↓
해당 카테고리 검색
↓
결과 출력
```

선택한 카테고리에 프롬프트가 없는 경우 안내 메시지를 출력해야 합니다.

## 4.8 프롬프트 검색

사용자로부터 검색 키워드를 입력받습니다.

검색 범위는 다음 두 영역입니다.

- 제목
- 내용

키워드가 제목 또는 내용에 포함된 프롬프트를 찾아 목록으로 출력합니다.

검색 결과가 없다면 별도의 안내 메시지를 출력합니다.

## 4.9 프롬프트 상세 보기

사용자가 프롬프트 번호를 입력하면 해당 프롬프트의 전체 정보를 보여줍니다.

### 출력 정보

## 7.3 Git / GitHub

### 커밋

최소 **10개 이상의 의미 있는 커밋**이 있어야 합니다.

단순히 커밋 개수만 늘리는 것이 아니라 기능 단위로 나누고, 커밋 메시지를 통해 어떤 변경을 했는지 설명할 수 있어야 합니다.

### 필수 Git 명령어

다음 명령어를 각각 **1회 이상** 사용해야 합니다.

| 명령어 | 역할 |
|---|---|
| `init` | Git 저장소 초기화 |
| `add` | 변경 파일을 스테이징 영역에 추가 |
| `commit` | 변경 사항을 하나의 버전으로 기록 |
| `push` | 로컬 커밋을 원격 저장소로 전송 |
| `pull` | 원격 저장소 변경 내용을 가져와 반영 |
| `checkout` | 브랜치 전환 등에 사용 |
| `clone` | 원격 저장소 복제 |
| `merge` | 다른 브랜치의 변경 내용을 병합 |

### 브랜치

브랜치 생성과 병합은 로컬에서 `checkout`과 `merge`를 사용해 수행하고 기록을 남겨야 합니다.

### 기본 데이터

이전 미션에서 작성한 프롬프트를 최소 **3개 이상** 기본 데이터로 등록해야 합니다.
