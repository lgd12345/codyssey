# AI 웹 개발: 내 아이디어를 현실로, AI 웹 서비스 빌딩

> AI 코딩 도구를 활용해 순수 HTML/CSS/JavaScript 프론트엔드와 Python 기반 Vercel Serverless Functions 백엔드를 구현하고, AI API를 연동한 웹 서비스를 실제 URL로 배포하는 과제입니다.

---

## 과제 한눈에 보기

이 과제는 크게 여섯 단계로 진행됩니다.

```text
1. 웹 서비스 아이디어와 타겟 사용자 정의
2. 3개 이상의 페이지/섹션과 AI 기능 설계
3. HTML/CSS/JavaScript 프론트엔드 구현
4. Python 기반 Vercel Serverless Functions로 AI API 연동
5. GitHub와 Vercel을 연결해 실제 URL로 배포
6. README·기획서·스크린샷·AI 코딩 도구 사용 증빙 제출
```

### 최종 제출 패키지

| 산출물 | 수량 | 핵심 내용 |
|---|---:|---|
| 배포된 웹 서비스 | 1개 | Vercel URL, 3개 이상 페이지/섹션, 반응형, AI 기능 |
| GitHub 저장소 | 1개 | 프론트와 `api/` 백엔드 구조가 구분된 프로젝트 코드 |
| README.md | 1개 | 서비스 소개, 기술 스택, 실행/배포 방법, URL, 환경 변수 |
| 서비스 기획서 | 1개 | 목적, 타겟, 페이지 구성, 핵심 기능, AI 입출력·실패 처리 |
| 증빙 자료 | 2세트 | 서비스 스크린샷 + AI 코딩 도구 사용 과정 |

### 반드시 충족해야 하는 핵심 조건

- 웹 서비스 아이디어를 직접 정의
- 최소 3개 이상의 페이지 또는 섹션 구현
- 메뉴를 통해 페이지/섹션 이동 가능
- 모바일에서도 정상 표시되는 반응형 구성
- 프론트엔드는 순수 HTML/CSS/JavaScript 사용
- React, Vue 등 프레임워크 사용 금지
- AI 기능 최소 1개 구현
- 사용자 입력 → API 요청 → 결과 화면 출력 흐름 구현
- `api/` 폴더에 Python 기반 Vercel Serverless Function 구현
- 프론트에서 `fetch('/api/...')` 방식으로 백엔드 호출
- AI API 키는 환경 변수로 관리
- API 키를 코드·README·스크린샷에 노출하지 않음
- GitHub와 Vercel 연동 배포
- 배포 URL에서 실제 기능 동작 확인
- README 작성
- 서비스 기획서 작성
- 데스크톱·모바일·AI 기능 동작 스크린샷 준비
- AI 코딩 도구 사용 과정 증빙 준비
- 예시 서비스의 아이디어·문구·구성을 그대로 복제하지 않음

# 1. 미션 소개

아이디어는 있지만 직접 웹 서비스를 구현하기 어렵다고 느꼈다면, 이번 미션에서는 AI 코딩 도구를 활용하여 아이디어를 실제 서비스 형태로 만들어봅니다.

목표는 단순히 코드를 생성하는 데 있지 않습니다.

직접 만든 웹 서비스를 인터넷에 배포하고, 다른 사람이 실제 URL을 통해 접속하여 사용할 수 있도록 만드는 것이 핵심입니다.

이전 미션에서 학습한 Python과 API 연동 경험을 바탕으로 다음과 같은 구조를 구현합니다.

```text
사용자
  ↓
웹 화면
  ↓
HTML / CSS / JavaScript
  ↓
fetch()
  ↓
Vercel Serverless Function
  ↓
Python
  ↓
AI API
  ↓
결과 반환
  ↓
웹 화면에 출력
```

AI 기능은 다음과 같은 형태로 자유롭게 설계할 수 있습니다.

- 사용자 입력에 맞춘 추천
- 문의 자동 응답
- 텍스트 생성
- 정보 요약
- 맞춤 안내
- 간단한 분석

AI가 코드를 대신 작성해줄 수 있지만, 이번 과제에서는 단순히 AI가 생성한 코드를 복사하는 것만으로는 충분하지 않습니다.

웹이 어떤 구조로 동작하는지 이해하고, 오류가 발생했을 때 다음 내용을 스스로 파악할 수 있어야 합니다.

- 어느 단계에서 문제가 발생했는지
- 프론트엔드 문제인지
- 백엔드 문제인지
- API 호출 문제인지
- 환경 변수 문제인지
- 배포 환경에서만 발생하는 문제인지

최종적으로는 자신의 아이디어를 기반으로 한 **AI 기능이 포함된 웹 서비스**를 실제 URL로 공개하게 됩니다.

### 페이지 또는 섹션

최소 **3개 이상**의 페이지 또는 섹션이 있어야 합니다.

예:

```text

```

페이지를 여러 HTML 파일로 구성하거나 하나의 페이지 안에서 여러 섹션으로 구성하는 방식 모두 가능합니다.

단, 사용자가 메뉴를 통해 각 페이지 또는 섹션으로 이동할 수 있어야 합니다.

### 반응형

웹 서비스는 모바일에서도 정상적으로 표시되어야 합니다.

즉,

- 데스크톱
- 태블릿
- 모바일

환경에서 레이아웃이 크게 깨지지 않도록 구현합니다.

최소 2가지 이상의 화면 크기에서 직접 확인해야 합니다.

### AI 기능

최소 1개의 AI API 연동 기능이 포함되어야 합니다.

기본 흐름:

```text
사용자 입력
    ↓
전송
    ↓
AI API 호출
    ↓
결과 수신
    ↓
화면에 결과 표시
```

## 3.2 사용자 입력부터 결과 출력까지의 흐름

사용자의 입력이 JavaScript를 통해 HTTP 요청으로 변환되고, 서버에서 받은 응답이 다시 화면에 표시되는 과정을 설명할 수 있어야 합니다.

```text
사용자 입력
    ↓
JavaScript 이벤트 처리
    ↓
fetch()
    ↓
백엔드 API
    ↓
AI API
    ↓
JSON 응답
    ↓
JavaScript
    ↓
HTML 화면 업데이트
```

## 3.3 Vercel Serverless Functions

다음 내용을 설명할 수 있어야 합니다.

- Serverless Function이 무엇인지
- 왜 AI API 키를 프론트엔드에 직접 넣으면 안 되는지
- 프론트에서 Python 백엔드를 호출하는 방법
- Python 백엔드에서 AI API를 호출하는 구조

기본 구조:

```text
브라우저
  ↓
/api/...
  ↓
Vercel Python Function
  ↓
AI API
```

## 3.4 환경 변수

## 3.5 로컬과 배포 환경

로컬에서는 동작하지만 Vercel 배포 후 동작하지 않는 상황이 발생할 수 있습니다.

다음 차이를 이해해야 합니다.

```text
로컬 개발 환경
vs
실제 Vercel 배포 환경
```

문제가 있다면 다음 과정을 반복합니다.

```text
오류 확인
  ↓
코드 또는 설정 수정
  ↓
GitHub 반영
  ↓
Vercel 재배포
  ↓
배포 URL 재검증
```

다음 중 최소 1개 이상을 사용자에게 안내 메시지로 제공해야 합니다.

#### 빈 입력

```text
필수값을 입력하세요.
```

#### API 오류

예:

```text
요청 처리 중 오류가 발생했습니다.
잠시 후 다시 시도해주세요.
```

#### 지연 / 타임아웃

응답이 늦을 경우 사용자에게 현재 상태 또는 안내 메시지를 보여줍니다.

예:

```text
응답을 생성하고 있습니다...
```

또는 실패 시:

```text

```

# 프로젝트 폴더 구조 예시

```text
my-ai-web-service/
│
├── index.html
│
├── css/
│   └── style.css
│
├── js/
│   └── main.js
│
├── images/
│   └── ...
│
├── api/
│   └── ai.py
│
├── requirements.txt
│
├── README.md
│
└── .gitignore
```

각 영역의 역할은 다음과 같습니다.

| 위치 | 역할 |
|---|---|
| `index.html` | 웹페이지 구조 |
| `css/` | 디자인·레이아웃·반응형 |
| `js/` | 사용자 입력, 이벤트, `fetch()` |
| `images/` | 이미지 리소스 |
| `api/` | Python 기반 백엔드 API |
| `requirements.txt` | Python 패키지 정의 |
| `README.md` | 프로젝트 설명 및 실행/배포 방법 |
| `.gitignore` | Git에 올리지 않을 파일 관리 |

# A1-3에서 특히 중요한 세 가지

## 1. 프론트와 백엔드의 역할을 구분하기

```text
프론트엔드
= 사용자에게 보여주고 입력을 받는 영역

백엔드
= API 키를 안전하게 보관하고 AI API와 통신하는 영역
```

AI API 키를 브라우저 JavaScript에 직접 넣지 않는 것이 중요합니다.

---

## 2. AI 기능이 실제 사용자 흐름으로 완성되어야 함

단순히 Python에서 AI API가 호출되는 것만으로는 충분하지 않습니다.

```text
웹 입력
→ 전송
→ AI 처리
→ 응답
→ 웹 화면 표시
```

전체 과정이 실제 배포 URL에서 동작해야 합니다.

---

## 3. 배포 후 검증까지가 구현의 일부

로컬에서 잘 동작한다고 과제가 끝난 것이 아닙니다.

```text
로컬 성공
≠
배포 성공
```

반드시 Vercel URL에서 직접 다음 내용을 재확인해야 합니다.

- 네비게이션
- 반응형
- AI API
- 오류 메시지
- 환경 변수
- 외부 사용자 접근
